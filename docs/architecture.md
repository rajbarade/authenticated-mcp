# Architecture

The process is an OAuth protected resource, never an authorization server. The client performs Entra authorization code + S256 PKCE and sends an access token; the server does not hold authorization codes, refresh tokens, or client secrets. No OAuth proxy, alternate issuer, Graph lookup, M2M grant, or premium application-group assignment is implemented.

FastMCP 4.1.3 runs stateless Streamable HTTP with JSON responses. An outer ASGI middleware protects every HTTP path/method except exact GET/HEAD health and metadata routes. It runs before transport dispatch; sessions cannot bypass authentication. The `TokenValidator` protocol yields an immutable provider-neutral `Principal`. Entra claim mapping is isolated from policy and tools. The tool is a plain Python greeting function.

PyJWT performs RS256 signature and exact issuer/audience/time validation. Required exp/iat/nbf are integer timestamps, required sub is checked by the library, and Entra oid/tid/ver/scp checks reject app-only tokens. An authenticated delegated token missing the required scope gets 403 insufficient_scope; malformed/absent delegated claims get 401. Groups missing, malformed, unrelated or indicated by overage all fail closed with 403. Group names and roles never substitute for group UUIDs.

Discovery is pinned to the configured public-cloud tenant. Both discovery issuer and discovered JWKS host/path must match the allowlist. Token jku/x5u cannot select a URL; kid only selects within trusted keys. RSA keys must be at least 2048 bits and suitable for RS256 verification; duplicate kid fails closed. Optional JWK issuer is tenant-bound too. Redirects and environment HTTP proxies are disabled. Response size is limited to 256 KiB and each network request times out after 5 seconds.

One lock serializes cache refreshes. Keys expire after five minutes; an unknown kid triggers a refresh at most once per 30 seconds per process. Newly rotated keys can therefore be temporarily rejected for up to 30 seconds. Refresh replaces the key set atomically. Expired caches are never used after refresh failure. An unexpired known key remains usable during an issuer outage; removed keys can remain usable until the five-minute cache expires. Token validation results are never cached.

Limits: group removal is reflected only in newly issued tokens; existing tokens remain valid until expiry. No continuous access evaluation or immediate revocation. No sovereign-cloud or multi-tenant support. Health is liveness, not proof of issuer reachability. Rate limiting, HTTP size/time limits, TLS, proxy header redaction and firewall policy belong to the host. Authentication logs contain fixed event/status/reason fields, no identity, token, body or query. Uvicorn access logs are disabled in documented commands.

Reference APIs reviewed 2026-10-25: [FastMCP token verification](https://gofastmcp.com/servers/auth/token-verification), [remote auth](https://gofastmcp.com/servers/auth/remote-oauth), [PyJWT](https://pyjwt.readthedocs.io/en/stable/usage.html), [MCP authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization). FastMCP's automated proxy pattern is intentionally not used; preregistration must be supported by the actual client.
